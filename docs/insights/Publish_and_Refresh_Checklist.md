# Publishing and refresh checklist
Documentation checked on 6 October 2026 using the Microsoft Learn references below. Tenant UI, permissions and capacity can differ. This is a deployment checklist; nothing has been published or scheduled by this project package.

## A. Before publishing
- [ ] Finish the report in Power BI Desktop; all source/model and DAX QA tests pass.
- [ ] Document FX source/as-of date/methodology and confirm costs' currency. Until then, default to NZD-only and expose FX status.
- [ ] Retain the partial-2019 labels; disable inappropriate totals on raw original-currency detail columns.
- [ ] Test all drill targets, especially ship-month rows crossing order-month boundaries; do not accept a wrong cohort.
- [ ] Verify tenant Azure Maps permissions; have the documented city-bar fallback.
- [ ] Check privacy/confidentiality of customer names, addresses and the original workbook before portfolio release.
- [ ] Decide whether actual data can be shared publicly. Publish to web is public internet distribution, not access-controlled sharing. Avoid it for confidential material. Screenshots should be sanitized when needed.
- [ ] Save an actual PBIX (or supported project format), and capture genuine screenshots of all six pages. Neither is generated by this package.
- [ ] Capture Performance Analyzer evidence if making performance claims; no benchmark improvement is claimed here.

## B. Workspace publication
- [ ] Confirm your workspace role and author/viewer license requirements with the tenant administrator. Requirements depend on license/capacity and sharing method; do not assume all viewers can use a free account.
- [ ] Choose the correct workspace; do not use a public link as a substitute for permissioned access.
- [ ] In Desktop, sign in and Publish; select the intended workspace. Publishing creates/updates the report and semantic model. Re-publishing can replace existing content; review warnings and downstream dependencies.
- [ ] Open the report in the Service, check default slicers, navigation, maps, tooltip behavior, mobile layout if required, and export permissions.
- [ ] Configure access through workspace/app/report permissions as appropriate. Hidden pages and hidden columns are not security boundaries; use actual permissions and RLS/OLS where applicable.

## C. Refresh with the Stage 1 local-file source
- [ ] The existing M uses File.Contents(pFilePath): publishing does not make the local workbook continuously reachable from the Service.
- [ ] Install/configure an on-premises data gateway on a supported always-available machine that can read the workbook. Prefer a stable managed network location rather than a temporary desktop/download path.
- [ ] Set pFilePath to a stable location accessible to Desktop and the gateway service account; verify filesystem/share permissions. Re-publish or update the supported parameter setting and connection mapping as appropriate.
- [ ] In semantic model settings configure gateway/cloud connections and data source credentials. Ensure the source path/mapping matches and the gateway host remains running.
- [ ] Alternative: move source to SharePoint Online/OneDrive for Business and deliberately replace local File.Contents with an authenticated cloud-source query; placing a locally synchronized file under OneDrive without changing the connector does not automatically remove the gateway dependency.
- [ ] Run Refresh now and inspect refresh history before enabling a schedule.
- [ ] Set schedule frequency/time zone and failure notification contacts. Since this source is a static 2017-2019 dataset, scheduled refresh has no benefit unless the source workbook will actually change.
- [ ] Microsoft documents up to 8 scheduled refreshes/day on shared capacity and up to 48/day for Premium/PPU/Fabric capacity settings. Check your actual tenant configuration and capacity constraints rather than assuming entitlement.
- [ ] Treat refresh times as target schedule times, not an exact execution guarantee. Monitor failure history, credentials expiry, gateway downtime, schema changes and invalid FX rates.
- [ ] Rates in the current DimCurrency query are M constants, not an editable Service input form. Change them in Power Query and re-publish/refresh, or redesign as an approved external rate table with its own refresh source.
- [ ] Validate after refresh: source row counts, unique keys, orphan foreign keys, Missing FX Rows, Duplicate Order Rows, negative lead times and reconciliation. If Order Number grain changes, revise operations averages and detailed visuals.

## D. Portfolio release
- [ ] README clearly separates implemented assets from report-building tasks still outstanding.
- [ ] Include model diagram, genuine report screenshots once available, code, source provenance, FX assumptions and analytical limitations.
- [ ] Verify download and repository links, exclude credentials/access tokens, and obtain data redistribution permission.
- [ ] Use the honest current-status resume bullets; switch to completed-report wording only after building/testing/publishing it.
